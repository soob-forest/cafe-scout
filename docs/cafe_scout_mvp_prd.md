# Cafe Scout PRD — 매출 추정 기능 반영 MVP 개정안

## 1. MVP 핵심 목표 변경

기존 목표:

> 카페의 특징을 빠르게 기록하고 여러 카페를 비교한다.

변경 목표:

> 카페의 특징을 3~5분 안에 기록하고,
> **메뉴 가격·좌석·고객 점유 상황을 바탕으로 예상 매출까지 추정한다.**

사용자는 카페 방문 후 다음 정보를 얻을 수 있어야 한다.

1. 어떤 콘셉트의 카페인가
2. 무엇을 잘하고 있는가
3. 가격대는 어느 정도인가
4. 몇 명 정도를 수용할 수 있는가
5. 현재 장사가 어느 정도 되고 있는 것 같은가
6. 이 구조라면 일 매출이 어느 정도 나올 것인가
7. 내 카페에 적용할 요소는 무엇인가

---

## 2. 현장 기록 화면 구조

현장 입력은 크게 6개 영역으로 구성한다.

```text
① 기본 정보
② 메뉴 / 가격
③ 좌석 / 고객
④ 운영 / 테이크아웃
⑤ 공간 / 분위기 / 평가
⑥ 예상 매출
```

---

## 3. 메뉴 / 가격 입력

### 목적

매장의 가격 포지션과 예상 객단가를 기록한다.

현장에서 메뉴 전체를 입력하는 것은 부담이 크므로 두 가지 방법을 제공한다.

### 방법 A — 메뉴판 사진

```text
메뉴

[ + 메뉴판 사진 ]
```

1~3장 첨부 가능.

MVP에서는 OCR로 자동 인식하지 않는다.

사진은 향후 참고 자료로 활용한다.

### 방법 B — 대표 메뉴 직접 입력

대표 메뉴만 3~5개 정도 빠르게 입력한다.

```text
대표 메뉴

아메리카노
[ 5,500원 ]

카페라떼
[ 6,000원 ]

시그니처 커피
[ 7,500원 ]

케이크
[ 8,000원 ]

[ + 메뉴 추가 ]
```

### 가격대

빠른 평가도 함께 제공한다.

```text
가격 수준

○ 저렴
● 보통
○ 높은 편
○ 매우 높음
```

---

## 4. 예상 객단가

매출 계산에서 중요한 값이다.

사용자가 직접 추정할 수 있도록 한다.

```text
예상 객단가

[-]  9,000원  [+]
```

또는 빠른 선택:

```text
[ 6천 ]
[ 8천 ]
[ 1만원 ]
[ 1.2만원 ]
[ 직접입력 ]
```

객단가는 단순 음료 가격이 아니라

> 고객 한 명이 실제 한 번 방문해서 사용하는 금액

을 의미한다.

예:

```text
아메리카노       5,500
케이크           8,000

2명 방문
커피 2잔 + 케이크 1개

총액             19,000

1인 객단가        9,500
```

---

## 5. 좌석 정보

매출 추정을 위해 좌석 수는 필수다. 값이 없어도 방문 기록 자체는 저장할 수 있지만 매출은 `추정 불가`로 표시한다.

```text
좌석

테이블 수
[-] 12 [+]

좌석 수
[-] 32 [+]
```

핵심 값은 **좌석 수**이며 테이블 수는 선택 입력이다.

---

## 6. 현재 고객 상황

정확한 인원 계수보다는 빠르게 기록할 수 있게 한다.

### 방법 A — 현재 고객 수

```text
현재 고객

[-] 24명 [+]
```

그러면 자동으로 표시한다.

```text
좌석 수       32석
현재 고객     24명

현재 점유율

75%
```

현재 고객이 좌석 수를 넘으면 고객 수는 그대로 기록하고 화면에는 `100%+`로 표시한다. 좌석 기반 매출 모델에는 최대 100% 점유율만 적용해 입석·대기 고객 때문에 매출이 중복 과대 추정되지 않게 한다.

### 방법 B — 점유율만 입력

세기 어려울 경우:

```text
좌석 점유

[ 25% ]
[ 50% ]
[ 75% ]
[ 100% ]
```

---

## 7. 평균 체류시간

회전율 계산에 사용한다.

```text
평균 체류시간

[ 30분 이하 ]
[ 1시간 ]
[ 1.5시간 ]
[ 2시간 ]
[ 2시간+ ]
```

정확한 값이 아니라 관찰 기반 추정값이다.

---

## 8. 테이크아웃

좌석 기반 매출만 계산하면 테이크아웃 중심 카페의 매출이 크게 왜곡될 수 있다.

따라서 선택 항목으로 제공한다.

```text
테이크아웃 비중

○ 거의 없음
● 조금 있음
○ 많음
○ 매우 많음
```

보다 정확하게 기록하고 싶은 경우:

```text
15분간 테이크아웃 주문

[-] 4건 [+]
```

---

## 9. 운영 시간

```text
영업 시간

10:00 ~ 22:00

총 12시간
```

영업시간은 기존 매장의 최근 방문값을 기본으로 제안한다. 사용자는 방문 당시 값으로 수정할 수 있고, 과거 매출 추정을 재현할 수 있도록 각 방문 기록에도 snapshot으로 저장한다.

---

## 10. 매출 추정 방식

MVP에서는 복잡한 재무 모델보다 이해하기 쉬운 모델을 사용한다.

### 좌석 기반 예상 주문 수

기본 개념:

```text
시간당 고객 수

≈

좌석 수
× 좌석 점유율
÷ 평균 체류시간
```

예:

```text
좌석       40석
점유율     75%
체류시간   1.5시간
```

계산:

```text
40 × 0.75 ÷ 1.5

≈ 시간당 20명
```

---

## 11. 일 매출 추정

단순히 현재 점유율을 하루 종일 적용하면 매출이 과대 추정될 수 있으므로 보정 계수를 사용한다.

```text
예상 일 방문객

좌석 수
× 평균 점유율
× 일 회전 수
```

그리고:

```text
예상 매출

=

예상 방문객
× 예상 객단가
```

---

## 12. 간단 매출 계산 예시

입력:

```text
좌석             40석
현재 점유율       75%
평균 체류         1.5시간
운영 시간         12시간
예상 객단가        9,000원
```

단순 계산상:

```text
시간당 고객

40 × 0.75 ÷ 1.5

= 약 20명
```

하지만 하루 종일 75%가 유지된다고 가정하지 않는다.

시간대 보정을 적용하여:

```text
예상 하루 고객

약 140명
```

이라고 추정했다면:

```text
140 × 9,000 = 1,260,000원
```

예상 일 매출:

> 약 **126만원**

## 13. 하나의 숫자 대신 범위 제공

현장 관찰만으로 정확한 매출을 계산할 수 없기 때문에 하나의 예상값을 제공하지 않는다.

```text
예상 일 매출

보수적
90만원

기준
126만원

활황
165만원
```

## 14. 예상 월 매출

영업일수를 입력할 수 있다.

```text
월 영업일

[ 30일 ]
```

결과:

```text
예상 월 매출

보수적
2,700만원

기준
3,780만원

활황
4,941만원
```

화면에서는 가독성을 위해 위 금액을 만원 단위로 반올림해 표시할 수 있지만 저장값은 SPEC의 정수 KRW 계산 결과를 사용한다.

## 15. 값의 출처 구분

현장에서 직접 확인한 정보, 사용자가 판단한 추정, 시스템이 계산한 값을 명확히 구분한다.

### 관찰값

```text
좌석           40석
현재 고객      30명
메뉴 가격       5,500~8,000원
```

### 사용자 추정값

```text
예상 객단가      9,000원
체류시간        약 1.5시간
테이크아웃 수준   조금 있음
```

### 시스템 계산값

```text
점유율           75%
예상 하루 고객   140명
예상 일매출      126만원
```

UI에서도 각각 `관찰`, `사용자 추정`, `시스템 계산` 배지를 표시한다. 점유율을 사용자가 직접 입력하면 `관찰`, 현재 고객 수에서 계산하면 `시스템 계산`으로 표시한다.

## 16. 매출 신뢰도

카페를 10분 본 것과 2시간 본 것은 추정 정확도가 다르다.

```text
매출 추정 신뢰도

●●○

보통
```

신뢰도 판단 요소:

- 좌석 수 입력 여부
- 현재 고객 수 입력 여부
- 객단가 입력 여부
- 체류시간 입력 여부
- 테이크아웃 관찰 여부
- 관찰 시간

---

## 17. 시간대 기록

P1에서 선택 기능으로 제공하며 P0 출시 조건에는 포함하지 않는다.

한 매장을 여러 번 방문할 경우 굉장히 중요한 데이터가 된다.

예:

```text
14:20 방문

좌석 40
고객 31

점유율
78%
```

다른 시간 방문:

```text
19:10 방문

좌석 40
고객 22

점유율
55%
```

누적:

```text
시간대별 점유율

11~14시    62%
14~17시    81%
17~20시    55%
```

이 데이터가 쌓일수록 매출 추정 정확도가 높아진다.

이 화면이 서비스에서 가장 중요한 결과 화면 중 하나가 된다.

## 23. MVP에서 제외할 것

- 메뉴판 OCR 자동 인식
- 네이버 지도 자동 연동
- 실제 카드 매출 데이터
- 상권 유동인구 데이터
- 임대료 자동 조회
- 원가 자동 계산
- 손익분기점 계산
- AI 분석
- 공개 회원 가입 / 초대 관리 / 프로필 / 역할 관리

공개 배포의 익명 접근을 막기 위한 사전 생성 운영자 계정의 로그인/로그아웃은 보안 기반 기능으로 제공한다.

특히 **메뉴판 OCR은 MVP 이후**로 둔다.

MVP에서는:

```text
메뉴판 사진 저장
+
대표 메뉴 가격 직접 입력
```

만으로 충분하다.

## 25. 제품 방향

이 변경으로 Cafe Scout는 단순한

> 카페 방문 기록 앱

이 아니라

> **카페 창업자가 경쟁 매장을 관찰하고 사업성을 추정하는 도구**

가 된다.

가장 중요한 데이터 구조는 결국 다음과 같다.

```text
CONCEPT
이 카페는 어떤 카페인가?

      +

CUSTOMER
누가 왜 오는가?

      +

UNIT ECONOMICS
얼마를 쓰는가?

      +

CAPACITY
몇 명을 받을 수 있는가?

      +

TURNOVER
얼마나 빨리 회전하는가?

      ↓

ESTIMATED SALES
그래서 얼마 정도 팔 수 있는가?
```

MVP의 핵심 차별점은 **“예쁜 카페를 기록하는 것”이 아니라 “잘되는 카페의 구조를 숫자로 기록하는 것”**이다.
